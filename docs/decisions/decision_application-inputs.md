# The application inputs: what a description may not state of a task's own code

- **Type:** `decision`
- **Date:** `2026-11-07`
- **Status:** `active`
- **External sources:** [the pinned Rust toolchain](../book/src/ledger.md#rust-toolchain) — the shape of the compiler's dependency information, which `crates/archogen-plan/tests/code_digest.rs` measures on every run, what it does not name, and the Cargo Book on build scripts, on `cargo rustc` and on profiles; [the Rust Reference](../book/src/ledger.md#rust-reference) — a crate as what one compile processes.
- **Owner / source:** leaf `M4.12`, from `ROADMAP.md` §10.3's "separately supplied application inputs", the runtime plan's `RTP-H5` and the release alarm's `RA-H7`. Review: leaf `M4.12.1`.

## The fact / decision

**In plain words.** A description says what a system is made of and what it must do, and never how a task's own code does it, so it cannot say how long that code takes, how much stack it needs or which calls it makes. Those figures belong to whoever wrote the code. A runtime plan today lists each of them as owed and says `(complete no)`. This is the one file that answers: `archogen-application/1`, written by a person or a tool, one per system, read by `crates/archogen-plan/src/application.rs`.

**What it holds.** The system and target it is for, what holds its code, one declaration of the whole application, the application's initialisation, and one clause per task:

```text
(format "archogen-application/1")
(system heartbeat)
(target hosted-playground)
(code (crate app) (place "../app") (digest "sha256:…"))
(leaves-interrupt-hardware-alone yes (clause "…the words below, whole…") (basis "it touches no device"))
(initialisation
  (entry-point "app::init")
  (stack-bound (value 256) (unit byte) (scope "its deepest path") (binary unbuilt) (evidence assumed) (basis "chosen, to be measured"))
  (node-calls (scope "all of it") (binary unbuilt) (evidence analytically-established) (locator "docs/argument.md") (basis "by reading")
    (call console.write 1)))
(task beat
  (entry-point "app::beat")
  (execution-bound (value 200) (unit us) (scope "one job") (binary unbuilt)
                   (evidence analytically-established) (locator "docs/argument.md") (basis "by the loop's bound"))
  (os-calls (scope "one job") (binary unbuilt) (evidence analytically-established) (locator "docs/argument.md") (basis "by reading")
    (call mask 2) (call unmask 2))
  (node-calls (scope "one job") (binary unbuilt) (evidence analytically-established) (locator "docs/argument.md") (basis "by reading")
    (call console.write 1))
  (masked-runs (scope "one job") (binary unbuilt) (evidence analytically-established) (locator "docs/argument.md") (basis "by reading")
    (run tail (ending unmask) (value 5) (unit us) (scope "the tail's update") (binary unbuilt)
              (evidence analytically-established) (locator "docs/argument.md") (basis "four loads")))
  (stack-bound (value 512) (unit byte) (scope "its deepest path") (binary unbuilt) (evidence assumed) (basis "chosen, to be measured"))
  (suspends no) (locks-scheduler no) (shares-outside-sections no)
  (masks-only-through-api yes)
  (figures-under-preemption yes)
  (deadlines-within-reach))
```

**Every clause is said, and nothing is defaulted.** A clause left out is refused naming it, one written twice is refused, and one this format does not know is refused, a language version among them, though a file of another format is told its format first, before anything the reader of forms says of its language's version: silence has no value, as in the rest of the engine. A list with nothing in it says so, `(deadlines-within-reach)` and an empty `(node-calls …)` among them. A task named twice is refused too. A file holds at most `MOST_BYTES`, 16 MiB, since a person writes it, and what is past that is refused by its length. What the reader of forms refuses is refused with what it said, a later version of the language on a file of this format among it.

**Each bound and each list of counts carries `ROADMAP.md` §7.3's record**, as a fact of its own: its scope, the binary it is of or `unbuilt`, and its evidence, one of the four categories `assumed`, `observed-maximum`, `externally-supplied` and `analytically-established`. A bound also has its value and unit, and a count's unit is calls. All but an assumption says where it can be checked, by a `locator`, and each says why, by a `basis`. So an empty list still says what backs it, as the composite-inputs record's §6 has it. A bound's observed maximum may give what it observed and a safety factor, which is held to its arithmetic, is at least one, so that it never shrinks what was seen, is kept for what reads it, and changes no category: a padded observation is still an observation. A list says `observed-maximum` alone, each of its counts being what was seen. Any other category says its name and no more, and one written with an observation is refused as saying more than its category.

**A masked run is one way of a run's ending.** Each `run` says `(ending unmask)` or `(ending completion)`, which the composition charges as `api.unmask` or `completion` (the composite-inputs record's §3), and a run that ends both ways is written once for each. Its bound has its own record, so it keeps its own category and any padding of its own, and the list's record is that of the counts inside. Its `call`s are the primitives it calls other than the `mask` and the `unmask` that delimit it, and its `node-call`s the nodes it calls.

**A node is written as the plan writes it,** its name or an instance's text, `(adapter KIND OVER)` or `(adapter KIND OVER REQUESTER)`, in `node-calls`, a run's `node-call` and `deadlines-within-reach`. A primitive is written by its name alone, in `os-calls` and a run's `call`.

**What each text can hold.** A text says something, a letter or a digit in it, on one line, with no control character, quote or backslash, since `/2` carries it on one line of a plan; a `place` alone may hold none, `..` naming the directory above (AI15-5). A name is no text: it is a symbol of the language, read as a description's is, so that what a plan can name a file can, `_` or a name holding a backslash among them. A `place` is a path from the file, its names joined by `/`, `.` and `..` among them, never one from the root; a name of dots alone is one of those two, so `...` is refused.

**The application's initialisation is named as a job is, or said to be none.** `(initialisation (entry-point "app::init") (stack-bound …) (node-calls …))` gives the path the boot calls before the first enabling of interrupts (`AI-H3`), that code's stack bound, and each node it calls a function of, a list with its record as a task's is: the clause lets application initialisation reach hardware through catalog functions, and the boot stack holds the deepest of them above its own bound (`decision_runtime-plan-format-2.md` §5). `(initialisation none)` says the application has no such code, and the declaration then rests on the tasks' bounds alone. A bound of code no build can call would bound nothing.

**Which code.** `ROADMAP.md` §1.1 has an application entry point resolve "to a declared, versioned source", through "a separate engine build manifest that associates logical task names with source or artifact inputs". **A run is part of its job.** What a run calls its job's lists hold, at least as many of each, and a run's own code is no more than its job's. The two calls that make it a run are among what it calls: the `mask` that begins it, and the `unmask` that ends one ending so, each one more than it writes inside. So a job with a masked run names `mask` among its `os-calls`, and `unmask` where a run ends by one. Each is refused where it is read, since the composition would otherwise take a `CS` past its `C`, or charge a job no `api.mask`. A run is looked up in its job's lists by a map, so this is in step with their lengths. **And a `mask` is held to a run**, a run being a stretch from a `mask` call: a job whose `os-calls` names `mask` states the runs it begins, since the composition would otherwise take its `CS` from no code at all. An `unmask` is held to no run's ending: a mask inside a mask is closed by one while its run ends at the job's completion (the fault contract's terms), so `mask; mask; unmask; return` is one run ending at completion, and its truthful file reads. A count may say more calls than a job makes, which only charges more.

**Times are a time and a stack is a size.** A time's unit is `s`, `ms`, `us` or `ns`, and a stack's `byte`, `KiB` or `MiB`, the language's, and each value is a whole number no less than nothing.

**A `binary` names an image by its image identity.** It is `unbuilt`, there having been no image, or the sha256 a build gives the image a figure was obtained on (`decision_runtime-plan-format-2.md` §1): of its plan's code identity and of what builds it, the toolchain, its flags and features, a flag remapping a directory held by the fixed name it gives alone, and none that names a directory of the build's own, `--out-dir`, `-C incremental`, `-L dependency` or `--extern`, which cargo passes and the build does not choose (AI13-6, AI14-4, AI15-1, `AI-H5`), the target it builds for, and the linker's input, by its objects' bytes and not an archive's member names, which a compile chooses afresh (AI12-8), but for the allocations. So a change of code, as far as `code`'s digest holds it (above), of toolchain, linker, feature or target moves it, as `ROADMAP.md` §9 asks of a bound tied to a binary. It is no digest of the image's file: a stack bound sizes its own allocation, which the linker is given, so the file moves with the bound and the identity does not. One identity names each image that differs only in where its allocations lie, its stacks and its tables, since a bound measured again moves every allocation laid after its own, and a bound is taken to hold of each, which is an assumption the scheduling checker names (`AI-H1`).
**An observation is of an image.** A bound or a list of counts of another image names that image's identity, and the build refuses it as stale (`AI-H3`). So an `observed-maximum` beside `(binary unbuilt)` is refused where it is read, of a bound, a list or a run: it names no image it was seen on, and a figure a build refused as stale would otherwise stand again by saying `unbuilt` (round 6). What reads here of an image is `sha256:` and 64 hex digits in lower case, whatever they are of.

**What it declares of the whole application is quoted, not named.** `leaves-interrupt-hardware-alone` is the fact every composite is gated on, and its name no longer says what it holds: since `M2.30` it holds the runtime's own data and code as well as the interrupt hardware. A plan's owed line shows the name alone. So this file quotes the whole clause, in the composite-inputs record's own words (its §2), which are these three parts, joined by ` … ` where that record goes on with what is no part of them:

> after the first enabling of interrupts, application code runs only as a declared task's job or as a service's application code; and no application code, a task's, a service's or application initialisation's, writes the timer's counter or compare, the interrupt controller's configuration, or the hart's interrupt or trap state other than through the runtime API's masking primitives (a job's only: the fault contract, Terms) or reads or writes the controller's claim and complete registers, a read of which claims, or a declared source's device registers; no service calls a runtime primitive; and no application code releases a task or calls a runtime function other than the runtime API record's primitives and its completion path. A runtime function is any function of a catalog record's implementation, a driver's included, called after the first enabling of interrupts; before it, application initialisation reaches that hardware only through catalog functions, which `runtime-discipline.<id>` covers.

> Application code calls no entry of the fault path — in initialisation, before the first enabling of interrupts, as in a job or a service's application code after it; a panic reaching the image's handler is no such call

> The runtime's own data is what this section's facts read in memory or in a register a port reserves: what the scheduler holds, its mask depth among it, what the timer service holds of the next release, the plan's tables, each saved context, and what a service, a record's or generated, holds of its source. ## Why

**One file, apart from the description**, since `ROADMAP.md` §10.3 keeps them apart: a description holds no implementation (`decision_eadl-engine-boundary.md`), and figures of a binary change with each build, where the description does not. **No default** for any clause, since a bound nobody stated reads the same as one somebody checked if the format supplies it. **The category beside each figure**, since §7.3 asks it and the composition reports each input by its category; a single category for a task would lose that its stack is assumed and its execution bound established.

**Quoting the clause and not a version of it.** A number or a digest would say which words were meant without showing them, and the point is that a person reads them. It costs a long line, which a tool can write.

**Rejected: a clause per fact in the description.** That is the first thing one would do, and it puts a binary's figures in the program, whose digest the assignment and the checker's verdict are of, so measuring the code again would move what was checked. `/2` carries them in the plan's text, whose digest is the plan's and is what they move: what an image holds of its plan must leave them out (`AI-H2`), since an image cannot name itself.
