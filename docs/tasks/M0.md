## Metadata

- Tree ID: `M0`

## Goal

Fix the controlling decisions the rest of the program depends on: the eADL/engine boundary
with a worked classification corpus, the `rt-static-up-v1` profile, the target selection,
the first fictional hardware and OS feature descriptions, the three use cases, and the
evidence/trust vocabulary — all recorded as durable records, not as conversation.

## Non-Goals

- No parser, resolver, analysis, or generation implementation. Those are `M1`–`M4`.
- No claim that the initial engine supports MMU/MPU, firmware mediation, DMA, power states,
  or multicore. Those are inventoried, not supported.

## Acceptance Criteria (roadmap exit gate, §12 M0)

- The feature descriptions contain no algorithms, drivers, model bodies, or lowering
  instructions.
- The worked boundary corpus and F27 cover ambiguous as well as obvious cases.
- One named physical target and its access path are recorded.
- The expected first generation result and its assurance limits are unambiguous.
- Each initial feature names its intended engine consumer.
- Board procurement/access problems are visible risks, never fictional passed gates.

## Decisions

- `2026-09-13`: the controlling boundary is recorded in
  `docs/decisions/decision_eadl-engine-boundary.md`. It is the precedence rule: it overrides
  ambiguous wording in any source draft and any later convenience argument. Every schema, kind
  registration and review cites it rather than re-deriving it.
- `2026-09-13`: the profile's exclusion list lives in code
  (`crates/eadl-model/src/profile.rs`) and the markdown page is checked against it. §3.1
  requires refusing an out-of-profile request *by name*; a name the engine refuses and a name
  the documentation publishes must not be able to drift apart.
- `2026-09-13`: an unknown capability is NOT admitted by silence. A known exclusion is refused
  by name with its reason; an unknown one is a `missing-fact` for the caller to resolve.
- `2026-09-13`: M0 runs concurrently with `S0`; `ROADMAP.md` §12 explicitly permits starting
  S0 from a minimal feature slice before M0's target decisions close.
