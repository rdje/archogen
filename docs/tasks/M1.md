# M1: eADL description foundation

## Metadata

- Tree ID: `M1`

- Created: `2026-09-13`

## Goal

Implement the typed, composable, implementation-free description foundation: S-expression
reading with source spans, namespaced imports, schemas, parameters, unit checking, functional
kind registration, and typed requirement normalization — enough language to express the
initial system completely at the feature/functionality level.

## Non-Goals

- No universal optimizer, no hundreds of device models (`ROADMAP.md` §12 M1 gate discipline).
- No implementation content in eADL: no algorithms, no code providers, no model bodies.
- No resolution or generation. Those are `M3` and `M4`.

## Acceptance Criteria (roadmap exit gate, §12 M1)

- Examples parse, type-check, and round-trip semantically.
- Importing and instantiating sub-HW and sub-OS modules works, including double instantiation
  without shared mutable elaboration state.
- Invalid examples produce source-localized diagnostics.
- At least twenty semantic examples exist: positive matches, relevant missing facts,
  conflicts, and unsupported cases.
- S0's executable-generation evidence is available before M1 is promoted as M3-ready.

  ### Design note — added `2026-09-27` by `M1.23`, which measured the trap

  ⚠️ **`BOOK-ANCHORS` cannot discharge this leaf's acceptance criterion, and reading it as though it
  could is the trap.** `scripts/check_book_anchors.sh:26-28` states its own limit verbatim: *"this
  proves a chapter points somewhere real, never that what it says about that place is true. Prose
  cannot be checked by grep. It removes the cheapest failure — a citation that has rotted — and leaves
  the expensive one to review."* A reference that cites real paths and states false rules passes it
  green. `M1.23` is the measured instance: both surfaces cited real code and published a figure that
  had been false for **47 commits**.

  So "every rule the frontend enforces is stated normatively" needs a mechanism of the shape `M1.11`
  gave the grammar — `crates/eadl-front/tests/conformance.rs` reads the EBNF **out of**
  `docs/semantics/grammar.md` and executes it, so the document cannot drift from the reader. Two legs
  follow, and both are census-shaped rather than prose-shaped:

  1. **Producer → reference.** Enumerate the codes the frontend can emit *from the producer*, and
     require each to be stated. The census must read the production half only, and must survive
     multi-line constructor calls — `Diagnostic::error(` and its code literal are frequently on
     different lines, so a single-line `grep` silently under-counts. What works:
     `awk '/#\[cfg\(test\)\]/{exit} {print}' <file> | tr '\n' ' ' | grep -oE 'Diagnostic::error\( *"[a-z0-9-]+"'`.
     Test-only codes must be excluded, not documented: `read-example` exists solely inside
     `diagnostic.rs`'s `#[cfg(test)]` module.
  2. **Reference → producer.** The mirror leg, so a renamed code leaves a rotted row rather than a
     stale truth. `docs/CLAIM_VERIFICATION.md` §3 leg 2 requires both directions; one direction alone
     is a population, not a count.

  ⭐ And per `M1.11`'s own honest limit, **value exactness is this leaf's to close** — it says so by
  name. `crates/eadl-front/tests/conformance.rs:24-28`, verbatim: *"What remains outside: this does
  not establish that the reader builds the right \*tree\* from those tokens, nor that it assigns the
  right \*value\* to each. A reader that tokenized identically and mis-nested, or that read `1.5` as
  three halves, would still pass. Nesting is the corpus suites' business (`corpus.rs`, the semantic
  cases); value exactness belongs to the language reference, leaf `M1.12`."* Token segmentation is
  already compared; value is not. A normative table of literal → exact value, read out of the
  reference and executed against the reader, is the leg that closes it — the same move that makes the
  EBNF normative rather than decorative.

  ⛔ **Carry no measured figure into the reference.** `M1.23`'s decision, recorded in Decisions below:
  a source header states the rule and names the test that measures; a figure appears only where a gate
  compares it to the measurement. The reference will be tempted to state counts — of codes, of
  clauses, of kinds — and each one is a future `M1.23`. Where a count is genuinely informative,
  derive it in the mechanism and let the prose name the mechanism.

## Decisions

- `2026-09-13`: the check **verdict is what to fix first**, not what was found first, and not
  severity of consequence. A malformed description makes every later answer meaningless; an
  unsupported request outranks a missing fact because describing that fact would be wasted work
  on a system the profile refuses anyway. Precedence chooses the headline, never what the author
  gets to see.
- `2026-09-13`: an **accepted description is silent**. "Accepted with three warnings" is a shape
  this pipeline does not have, so an author never has to judge which messages mattered.
- `2026-09-13`: the kind modules are **embedded in the binary**, not read from the working
  directory. A language definition that a file in the current directory could shadow is a
  language definition an accident can change.
- `2026-09-13`: `Verdict` is the single §5.5 vocabulary and its mapping to exit codes is
  asserted **total**. A second enum spelling the same seven words is the drift.
- `2026-09-13`: a clause declared `(holds kind …)` is validated **recursively**, and that is
  how the schema's reach grows. Every clause moved off `(holds forms)` extends it by exactly
  what that clause contains — the 10/11 gap closed to 13/13 by moving one.
- `2026-09-13`: a registry that cannot validate a clause **says so**
  (`schema-unknown-referenced-kind`). Silently accepting whatever is inside an unvalidatable
  clause is the failure mode that let the gap exist.
- `2026-09-13`: a **composition reference is not a fact request**. `(requires (uses
  timer.counter))` names a declared block, satisfied by its declaration; only a name that is
  neither declared, offered, nor a service is a missing fact. Being declared does not repeal an
  explicit absence, so the absence check runs first.
- `2026-09-13`: an abstract description states **bounds with a direction**
  (`(counter-width (at-least 32 bit))`), not bare values. §5.2 warns that more is not
  universally better, so a bare value would leave the checker guessing — and guessing right for
  a counter width while guessing wrong for a delivery bound.
- `2026-09-13`: refinement separates **violations** from **additions**. §5.1.1 demands the
  obligations be checked and §5.3 says an unused device is not automatically invalid; the
  exclusion obligation is where the two meet, and it is the one a naive "the concrete may say
  more" rule silently drops.
- `2026-09-13`: F04 and F05 are tested against **one description**, not two. They are two
  halves of a single decision about relevance; separate descriptions could be passed by two
  different bugs — "always block" and "never block" — each satisfying one half.
- `2026-09-13`: **absent ≠ undescribed.** A required absent fact is `infeasible-configuration`;
  a required undescribed one is `missing-fact`. Collapsing them would tell an author to go and
  describe something the platform has already said it does not have.
- `2026-09-13`: elaboration produces **instances, not modules**. §5.1.1 requires instantiating
  a module more than once without shared state; a cache keyed on module name would be smaller
  and would silently make the second import a no-op, so a system with two timers would have one.
- `2026-09-13`: a **cycle** is the only composition failure that stops elaboration, because
  continuing into one does not terminate. Everything else is collected, so three problems cost
  one edit cycle.
- `2026-09-13`: **no floating point anywhere in the toolchain.** §7.4 requires exact integer or
  checked rational arithmetic; a magnitude is an exact `i128/i128` rational, every operation is
  checked, and a value with no short decimal form prints as a fraction rather than being rounded
  into something that reads like a measurement.
- `2026-09-13`: `ComparisonDirection` has **no default**. §5.2: "more bits or a faster clock is
  not universally better." An undeclared direction is a bug waiting for a substitution to
  expose it, so the type refuses to guess.
- `2026-09-13`: **exactly one declaration is a trusted primitive** — `defkind`, whose meaning
  is `crates/eadl-model/src/kind.rs`. All five surface kinds are declared in eADL in
  `docs/semantics/kinds/core.eadl` and are no more privileged than a kind added tomorrow. §2
  requires the trusted foundation to stay explicit; a second primitive would have to be written
  in Rust, where it is visible.
- `2026-09-13`: the schema and the boundary classifier are **independent and unequal in reach**,
  measured rather than assumed: 10 of 11 rejected corpus cases versus 11 of 11. Two independent
  refusals for the same content is a feature — a mistake in one is caught by the other — and
  claiming they were equivalent would have been the more dangerous kind of green.
- `2026-09-13`: the reader is **purely syntactic**. `(tick-rate 10 MHz)` is a symbol, an
  integer and a symbol; that `MHz` is a unit belongs to `eadl-model`. That is what lets one
  reader serve the boundary corpus, the S0 fixture and the M1 semantic corpus without any of
  them leaking assumptions into the others — and it is why `M0.3` and `S0.2` do not each grow
  a throwaway parser.
- `2026-09-13`: **there is no float in the reader.** §7.4 requires exact integer or checked
  rational arithmetic; a decimal literal is kept as an integer and a scale, so `0.1` survives a
  round trip exactly. An out-of-range literal is refused, never wrapped.
- `2026-09-13`: comments are **kept**, with spans. They are inert to the language, and the
  boundary corpus carries its case metadata in them — discarding them would force a second,
  divergent parser to exist just to read those headers.
- `2026-09-13`: draft surface syntax may change until the first compatibility baseline; once
  frozen, migration notes are mandatory (`ROADMAP.md` §12 M1, §15).
- `2026-09-27`: **a measured figure is published in prose only where a test compares it to the
  measurement.** `M1.23` found the schema's reach hand-copied into three live surfaces; `M1.7`
  moved the measurement and updated one of them, so two stayed false for 47 commits and the book
  contradicted itself between chapters. The rule that follows is not "retype the number" — that is
  the anti-pattern `docs/CLAIM_VERIFICATION.md` §5B names — but: a *source header* states the rule
  and names the test that measures, carrying no figure at all, and a *book chapter* may carry the
  figure because a gate reads the chapter and compares. Corollary, and the reason the gate accepts
  past tense: a figure describing an **older** measurement is a record and stays, marked as
  history; only a figure presented as current must match. Records are never re-derived.

- `2026-09-27` (`M1.24`): **an escape clause in a figure gate must be an explicit list, never a
  tense scan.** This *corrects the mechanism* in the entry above while leaving its rule standing: a
  figure describing an older measurement is still a record and still stays. What changed is how a
  gate recognizes one. Excusing a non-current figure because its line contains `was`/`before`/
  `previously` was measured failing on its own defect — the corpus index's stale line quotes
  `ROADMAP.md` §4.3 (`…worked classification case before adoption"`) seven words ahead of the wrong
  number, and the gate reported green. A substring anywhere in a line is not a tense; it is a
  coincidence. History is therefore something an author **lists** in a constant, where adding a line
  is visible in review. `the_live_surfaces_publish_the_measured_corpus_size` uses
  `HISTORICAL_FIGURES` (empty today); `the_live_surfaces_publish_the_measured_reach` still uses the
  marker scan and is `M1.25`'s.
- `2026-09-27` (`M1.24`): **a census result is incomplete without the pattern that produced it.**
  Three sweeps with three patterns were needed to find one defect class, and each sweep's "nothing
  else found" was true only of its own shape: `N of M` could not see a corpus *size*, digits could
  not see `the five ambiguous cases`, and neither could see `all six leaves`. A figure can be
  spelled as digits, as a word, or as a ratio, and a population bounded by one spelling is not a
  population. Recorded in `docs/knowledge/a-moved-measurement-needs-a-census-of-its-copies.md`
  step 1, and it is why `PROGRAM.20` exists rather than a fourth sweep.

- `2026-09-28` (`M1.12.1`): **the language reference is executed, and its expected values are
  derived rather than transcribed.** `docs/semantics/reference.md` states each literal's worth as a
  table of `literal → value → canonical text`, and `crates/eadl-front/tests/reference.rs` reads the
  table out of the document and runs every row against the frontend — the same move that made the
  EBNF normative rather than decorative. The values come from arithmetic (`0x1000_0000` is 16^7),
  from §7.4, or from a decision recorded here; never from printing what the reader produced, because
  a table transcribed from the implementation is as unfalsifiable as no table. **Measured payoff:**
  the first run found three defects rather than confirming one — F-B, F-D and F-E below.

- `2026-09-28` (`M1.12.1`): **canonical text carries no control character.** Line feed, tab and
  carriage return are escaped on the way out exactly as they are decoded on the way in, so the text
  §12 M4 hashes and compares stays one form per line and survives a diff, a terminal and an editor.
  A raw carriage return was reachable and measured: `diagnose` on `(probe "a\rb")` piped to `od -c`
  showed the control byte, and a terminal read it as "back to column zero", overwriting the start of
  its own line. `crates/archogen-s0/src/provenance.rs` already escaped `\r` in its own quoting, so
  the rule existed in the project and was simply missing from the normative printer. The leg that
  enforces it is a **property over every row**, not one row's expectation.

- `2026-09-28` (`M1.12.1`): **the sign is applied after the magnitude is parsed, in a wider domain
  than the value it becomes.** `-9223372036854775808` is `i64::MIN` and was refused as overflow,
  because its magnitude is `i64::MAX + 1` and the reader parsed it as an `i64` before negating — so
  the range the language claims had exactly one unwritable value. Both conversion sites now share one
  helper, which is the point: the wrong order can no longer be written twice. Out of range is still
  refused and never wrapped.

- `2026-09-28` (`M1.12.1`): **a separator separates digits; it does not lead them.** `0x_10` read as
  16 while `docs/semantics/grammar.md` refused it, and the reader's own decimal path could never
  begin with `_` — hexadecimal was the one literal form whose leading character nothing policed. The
  reader was tightened to the grammar rather than the grammar widened to the reader, because the
  stricter rule is the one that was already written down and the looser spelling is never intentional.
  ⚠️ The mirror-image cases — `0X10`, which the reader accepts and the grammar forbids, and `\0`,
  which the grammar allows and the reader refuses — are **not** decided here: they are `M1.12.2`'s,
  because that leaf is the first one with a mechanism that can prove the resolution.

- `2026-09-28` (`M1.12.2`): **`0X10` is a hexadecimal literal and `\0` is not an escape — and both
  were settled by changing the grammar, not the reader.** The prefix is now `( "0x" | "0X" )`, because
  the reader has always read `0X10`, its digits were already case-insensitive, and a case-*sensitive*
  prefix would be the one inconsistency in the literal; canonical form prints `16` either way, so no
  ambiguity survives into a plan. `escape` no longer admits `"0"`, because the reader never implemented
  `\0`, a NUL byte has no use in a description, and `read-bad-escape`'s own hint already enumerated the
  set that exists. ⛔ Neither spelling appears in any description the repository ships, so this was
  decided on the normative documents and not on observed use — which is what `M1.13`'s freeze makes
  expensive, and what doing it now avoids.

- `2026-09-28` (`M1.12.2`): **`error` and `refused` are different claims, and the reference now says
  so.** `error C` means the literal is *not well-formed* and the grammar must reject it; `refused C`
  means it *is* well-formed and its value lies outside the domain the language can hold, so the grammar
  must accept it and the frontend refuse it. A syntax that could express "too large" would have to know
  the width of the value domain — precisely the implementation detail `docs/semantics/grammar.md` keeps
  out of itself. This is what let one table drive both legs, and it is why `9223372036854775808` and
  `1.2.3` are not the same kind of mistake.

- `2026-09-28` (`M1.12.2`): **one normative document gets one parser.** The reader for
  `docs/semantics/reference.md`'s tables moved to `crates/eadl-front/tests/common/reference_table.rs`,
  shared by `reference.rs` and `conformance.rs`. Two parsers for one normative table would be two
  things that can disagree about what the rule *says*, before either asks what it means — the failure
  the grammar exists to end, one level up. `#![allow(dead_code)]` on that module is deliberate and
  documented: cargo compiles each integration test as its own crate, so an item one suite uses and the
  other does not is dead code in the second, and this workspace runs clippy at `-D warnings`.

- `2026-09-28` (`M1.12.3`): **a normative document declares what it governs, in a table a test reads.**
  `docs/semantics/reference.md` lists the sources it is normative over, and the diagnostic census takes
  its population from that list rather than from a constant inside a test. Adding a source is then a
  reviewable edit to the document, which is where a claim about scope belongs; a list in the test would
  be a second definition of scope, and the two would drift the way every other pair in this project
  has.

- `2026-09-28` (`M1.12.3`): **a census leg runs in both directions, or it has an empty-set fixed
  point.** A producer→document leg passes when the scanner finds nothing: every row is then unexplained
  by nothing and the two sides "agree". Measured, the grep shape this would have been written in —
  code on the constructor's own line — finds **0 of 7** codes in `reader.rs`, **0 of 24** in
  `module.rs` and **0 of 22** in `kind.rs`, because every call here puts the code on the next line.
  So the mirrored leg is not a symmetry preference, it is what makes a broken scanner fail; and a guard
  reports an empty population outright, because "the census found nothing" and "the census looked in
  the wrong shape" are the same sentence.

- `2026-09-28` (`M1.12.4`): **a table of rules has to pin the cases where the rule says *nothing
  happens*.** §5's header table carries rows whose expectation is that the block yields no header at
  all, and the leg refuses a table that only ever yields one or only ever refuses. A table of
  successful parses passes on an implementation that treats every comment as a header, which is the
  same shape of false green as the empty-set census above: the case that discriminates is the negative
  one. Both header discriminators are therefore load-bearing *from the document*, and an arm proves
  each by editing a row rather than the code.

- `2026-09-28` (`M1.12.4`): **canonical text is read back, not only compared.** Every literal row now
  round-trips: the frontend's canonical text is re-read and must be structurally equal to what produced
  it. Comparing the text against a stated cell pins the spelling; re-reading it pins the *contract* —
  that canonical text is a description the language accepts and means the same thing. Finding F-D
  violated exactly that, and the control-character property catches only the control-character case.

- `2026-09-28` (`M1.12.4`): **`boundary.rs` is deliberately not a normative source of the language
  reference.** It classifies implementation syntax, which is a *profile* concern documented in
  `docs/book/src/boundary.md`, not a rule of the language. Declaring it would demand a row for every
  code it emits while no chapter of the reference explains what any of them means — the failure mode
  the declaration exists to prevent, arrived at from the other side. A normative document's scope is a
  claim, and the claim is worth less for being wider than the document.

- `2026-09-28` (`M1.12.5`): **the reference governs the *surface*, and the surface is not the whole
  toolchain.** §4's declaration is read as the authority on which codes this document states, and the
  cross-surface leg takes its governed prefixes **out of the declaration's own words** ("every
  diagnostic in §4 whose code begins `read-`") rather than from a list in a test — so the scope moves
  when the document does. The consequence is a deliberate asymmetry, and it is recorded because it
  looks like an omission: a diagnostic the book renders is checked for **existence** whatever emits it,
  and for **meaning** only when §4 governs it. The model layer's codes — quantities, presence,
  refinement, the profile check — are real diagnostics the director is shown, and no normative document
  states them. Widening the reference to cover them would make it normative over *meaning*, against its
  own §7 rule 5. So they are owned by `M1.26` with their census, and leg 8's honest limit names them.

- `2026-09-28` (`M1.12.5`): **a deferral is a claim, and it is re-measured when the population moves —
  the parent's acceptance does not need the `fires on` column, but the reason recorded for deferring it
  is false.** `M1.12.3` deferred an executable input column on §4's table for two reasons: it needs
  notation for a control character, and *"the reachability it would add is already covered per-code by
  `reader.rs`'s own unit tests."* The first still holds. The second was measured, and it holds for the
  seven codes `M1.12.3` could see (`read-` 7 of 7 asserted by a test) and not for the forty-six
  `M1.12.4` added afterwards (`module-` 11 of 24, `schema-` 10 of 22) — **25 of 53** stated rows are
  named by no test. Two separate judgements follow, and conflating them is the trap. `M1.12`'s
  acceptance asks that every rule the frontend enforces *be stated* and *cite what enforces it*; legs 4
  and 5 pin that exactly, at 53 stated / 53 emitted / 0 rotted rows, so the parent closes. Reachability
  is a different property that no criterion asks for — but the absence is real, it is the shape
  `M1.23` and `M1.24` were both burned by, and it is now `M1.26`'s gap (b) with its census attached.
  ⛔ What the census does **not** show: that any of those 25 codes is unreachable. A test can trigger a
  diagnostic while asserting only `has_errors()`. It is an absence of evidence, not twenty-five defects,
  and it is filed as such.

- `2026-09-28` (`M1.13`): **the freeze is five children ordered by dependency, not by preference.**
  Two of the three acceptance criteria change the language, and a leaf that both changes a construct and
  freezes it cannot show a clean before→after for either — the same reason `M1.12` decomposed. So the
  two value-domain findings land first, then the version identifier, then the baseline, and only then
  the gate that enforces it: a baseline written before the last language change would freeze a
  construct the same commit goes on to edit, and a gate written in the same commit as its baseline
  cannot be shown firing on the real tree.

- `2026-09-28` (`M1.13`): **F-F's recorded impact is corrected, not carried forward, and the domain
  stays 64-bit for `eadl/1`.** `M1.12` routed the finding with the claim that a memory-mapped base
  address in the upper half of a 64-bit address space cannot be described and that `M2.8.2`'s
  device-tree fixture is where it would first matter. The pinned RISC-V privileged spec contradicts the
  premise: RV64's PMP registers encode bits 55-2 of a **56-bit** physical address, Sv39 and Sv48
  support a 56-bit physical address space, Sv57 is 57-bit *virtual*, and Sv64 is reserved and
  unimplemented — so nothing a standardized target can have reaches 2^57, against a domain limit of
  2^63−1. The census agrees from the other side: the largest of the 27 distinct literals in the whole
  tracked corpus is `0x1000_0000`. ⭐ The decision that follows rests on a property of *this* change and
  not on a general rule about freezes: **a widening is backward compatible**, so every literal readable
  under `eadl/1` keeps its value and deferring costs one added compatibility-corpus row rather than a
  migration. That is why the "pre-freeze is the free moment" argument, which sequences `M1.13.1` first,
  does not also force the widening into `eadl/1`. Recorded on the leaf with both censuses; promoted to
  `docs/decisions/` by `M1.13.2`.
  ⛔ **Corrected on promotion, and the correction is the reason the promotion was worth doing.** Both
  measurements this entry rests on moved when `M1.13.2` re-derived them rather than carrying them: the
  census figure was scoped and radix-qualified in ways the sentence dropped (the largest literal in the
  tracked corpus is **2^32**, not `0x1000_0000`, and the population holds **24** distinct integer
  values over 194 occurrences with **0** refused by the domain), and "nothing a standardized target can
  have reaches 2^57" is true of *physical* addresses and false of canonical *high-half virtual* ones,
  which are above the domain as magnitudes under Sv39, Sv48 and Sv57 alike. The **decision is
  unchanged** — the domain stays exact signed 64-bit for `eadl/1` — and now rests on a reason that
  survives the measurement: a widening is compatible, and every value that needs one is already
  reachable as a signed value. `docs/decisions/decision_eadl1-value-domain.md` carries the corrected
  argument, both censuses as re-runnable commands, and the three named triggers that would make it
  wrong. This entry is left standing as the record of what was decided on `2026-09-28` and on what.

- `2026-09-28` (`M1.13`): **a version identifier cannot ride the comment-header convention.** It is the
  obvious candidate — no grammar change, §5 already makes one shape of comment data, and
  `Document::comment_headers()` already reads it — and it is wrong, because §3 states canonical form
  carries no comment and §12 M4 hashes canonical plans. A version in trivia is a version the hashed
  artifact does not capture, so two descriptions claiming different language versions would hash
  identically. The identifier has to be a **form**, which is a grammar change and is free only before
  `.4` writes the baseline. Owned by `M1.13.3`, which also decides — and records, with the census of
  what it touched — whether an absent identifier defaults to `eadl/1` or is refused.

- `2026-09-28` (`M1.13`): **F-G is fixed in the printer first and at the reader second.** The reference
  poses it as "either a general escape **or** a rule that a description may not contain one", and the
  measurement shows the choice is not free. §3 rule 5 requires canonical text to read back to a
  structurally equal document, so an escape the printer emits and the reader refuses would trade F-G
  for a round-trip defect; and `Form::Str` is constructible outside the frontend — `lib.rs` re-exports
  `Form` and `Span`, enum variant fields inherit the enum's visibility, and `Span::new` is `pub const
  fn` — so refusing input closes one route into the value and not the only one. `docs/knowledge/make-the-rule-a-constructor-precondition.md`
  names the shape: refuse the illegal *state* (canonical text holding a control byte) where it is
  produced. Owned by `M1.13.1`, whose RED arms must use raw control bytes as fixtures, including NUL,
  because both existing legs read populations that cannot contain one.

## Open Questions

- None blocking the frontier.
- The two value-domain decisions are **decided in direction and scheduled rather than open**: F-F
  (no writable value at or above 2^63) keeps the 64-bit domain for `eadl/1` and becomes a stated
  property of the version — `M1.13.2`; F-G (no escape for a control character other than `\n \t \r`)
  becomes a total printer plus a uniform reader rule — `M1.13.1`. Both were re-measured `2026-09-28`
  on `M1.13`'s leaf, and both measurements moved the finding: F-F's recorded impact rested on a premise
  the pinned ISA spec contradicts, and F-G's fix shape is constrained by §3 rule 5 and by `Form::Str`
  being constructible outside the frontend.
- ⭐ One question stays genuinely open and is `M1.13.3`'s to answer, not this tree's to pre-decide:
  whether an **absent** version identifier defaults to `eadl/1` or is refused. Defaulting is friendlier
  to the 62 existing corpus files and weaker as a lock; refusing is a strengthening that pre-freeze
  costs one pass over the corpus. Whichever is chosen goes in the decision record with the census of
  what it touched.
- ⛔ **What the language's own name stands for, and whether "Extended" is a claim this tree can
  support.** Raised `2026-09-29`. Two measurements first:
  - **The acronym is expanded nowhere in the repository.** Census: searching `README.md`, `ROADMAP.md`,
    `docs/book/src/` and `docs/semantics/` for an expansion of `eADL` returns only `.eadl` inside
    command examples — so `ROADMAP.md` §1 uses the term from its first sentence and never says what it
    is. The director supplied the expansion: **Extended Architecture Description Language**, supplied
    with the caveat that it is *not clear in what way it is extended*.
  - **"Extended ADL" does not describe the syntax, because the ADL tradition is not s-expression
    based.** Acme, Wright (CSP-style process algebra), Rapide (event patterns), UniCon, C2, Darwin and
    **AADL** (SAE AS5506 — its own text syntax, an XML system model, and OSATE's graphical editor) each
    carry their own notation. eADL's surface is an s-expression family (`docs/semantics/grammar.md`), a
    different lineage from all of them, so the name inherits nothing from the syntax side either. And
    the prior art is cited nowhere: `grep -rniE '\bAADL\b|AS5506|42010|Acme|Archi|UniCon|Rapide|\bC2\b|OSATE|Wright'`
    over tracked `.md` outside `vendor/` → **0** real hits (the matches are "architecture port",
    "MEMORY_ARCHITECTURE", "five architectures").
  Three honest readings, and **the choice is the director's, not this tree's**:
  **(a) extended past description into generation** — a classic ADL is read by a human or analysed by a
  separate tool, while an eADL description is *compiled into* a complete specialized OS with an
  independent checker. This is `ROADMAP.md` §1's own claim and `decision_eadl-engine-boundary`'s
  subject, so it is the reading the repository already supports without new work.
  **(b) extended as *extensible*** — the language grows using its own declaration constructs (`defkind`,
  §7 of the reference), which is a literal sense of the word and is executed rather than asserted.
  ⭐ **This is the reading the director's own rationale selects**, supplied `2026-09-29`: *"code and
  data wear the same cloth … they have the exact same syntax and it is inherently extensible."* Recorded
  in full on `M1.13.3`'s leaf, with the limit that belongs beside it — eADL is homoiconic in its syntax
  and deliberately not in its execution, there being no `eval` and no macros, because a macro is
  implementation and `decision_eadl-engine-boundary` keeps implementation out of the description.
  **(c) no expansion at all** — keep `eADL` as a name that stands for nothing, which is legitimate
  (`Rust` and `Zig` expand to nothing) and cheaper than defending a word.
  **Owner: `M1.13.3`**, because that leaf puts the identifier `eadl/1` on the surface and is therefore
  the one that fixes the language's *name*; publishing "Extended" across the authoritative surfaces
  before it decides would lock an undefined term into exactly the documents the freeze covers.
  ⚠️ Recorded so the near-miss is visible: expansions were drafted into `README.md`, `ROADMAP.md` §1 and
  `docs/book/src/introduction.md` and then **reverted byte-identical to `HEAD`** (`diff -q` against
  `git show HEAD:` silent on all three) rather than committed, because the director's own uncertainty
  about the word is a reason not to publish it — not a reason to publish it quietly and let a reader
  discover that nothing in the tree says what it extends.
