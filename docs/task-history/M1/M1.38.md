- ID: `M1.38`
  Status: `done`
  Goal: the reader refuses a list nested past a stated limit, and never exhausts its stack.
  Reproduce / issue: found `2026-09-30` while measuring the abuse surface for `API.4` (limits on a description from
  an untrusted consumer). A description of nothing but nested parentheses crashes the reader:
  ```text
  depth 1 000 · 2 000 · 4 000 · 6 000 → archogen check exit 10 (schema-not-a-declaration)
  depth 8 000 · 10 000 · 100 000     → exit 134: "thread 'main' has overflowed its stack", Abort trap: 6
  the reader alone (cargo run -p eadl-front --example reader_shape) crashes at the same depths
  census: the deepest tracked description nests 6 levels (docs/semantics/boundary/reject/register-programming-sequence.eadl)
  ```
  A debug build, with the main thread's default stack. A 16 KB file ends the process outside the exit contract:
  neither a verdict nor `tool-failure`. For the MCP server `API.6` will spawn, one message from any agent would
  do it. `read_list` recurses once per level (`crates/eadl-front/src/reader.rs`), and so does every pass that
  walks a form afterwards, including dropping it.
  Acceptance: a stated nesting limit, far above any real description and far below the crash; the reader refuses
  the first list past it with its own §4 code and reads nothing inside it, so no later pass sees the depth; a
  migration note, since §4 is frozen; the `fires on` cell written without 257 literal parentheses, through a
  repetition marker in the table notation beside `<0xNN>`; the crash measured gone at depths far past the old
  one; probes at the limit (accepted by the reader) and one past it (refused); `make focused` exit `0`.
  Priority: **high** — a crash reachable from a 16 KB input, and the precondition for `API.4`'s limits.
  **Closed `2026-09-30`.** `MAX_NESTING = 256` in `crates/eadl-front/src/reader.rs`. The reader counts open lists,
  refuses the first past the limit as `read-nesting-too-deep`, and steps over it with a loop that honours strings
  and comments. A new §4 row carries its migration note, and the table notation gains `<N*C>`, so the `fires on`
  cell reads `check <257*(><257*)>`. The grammar says the depth is deliberately not in the EBNF, and the book's
  reading chapter says why the limit exists. The census found no tracked description near it: the deepest nests 6.
  Verification: see the checklist.
