- ID: `M1.39`
  Status: `done`
  Goal: a module tree is bounded — in how many instances it elaborates into, and in how long an import chain may be —
  so a small description cannot exhaust memory or the elaborator's stack.
  Reproduce / issue: found `2026-09-30` measuring `API.4`'s abuse surface, right after `M1.38`. Two ways, both
  through `archogen check` on module files in a directory:
  ```text
  fan-out — module i imports module i+1 twice (as a, as b); k links → 2^(k+1)−1 instances
    k=8: 511 instances, 0.01 s · k=12: 8 191, 0.19 s · k=16: 131 071, 3.21 s · k=18: 524 287, 12.84 s, 1.8 GB RSS
    (19 files of about 100 bytes each; every extra link doubles time and memory)
  chain — module i imports module i+1 once
    1 000 links: exit 0 · 3 000 and 6 000 links: exit 134, "thread 'main' has overflowed its stack"
  census: the largest tracked module tree elaborates into 4 instances (docs/semantics/modules/app.system.eadl),
          and the longest chain is 3 modules
  ```
  Each instance re-reads and re-parses its module (`crates/eadl-front/src/module.rs`, `instantiate`), so fan-out
  multiplies text, forms and spans. `instantiate` and `instantiate_source` recurse once per link. Through the engine
  API a consumer supplies the modules in memory, so one request would do either.
  Acceptance: an instance limit and an import-depth limit, stated in the reference as properties of `eadl/1`, each
  with its own §4 code and an executed `fires on` cell; elaboration stops at the first limit reached, with one
  refusal, so the work done past it is bounded; a migration note, since §4 is frozen; the crash and the blow-up
  measured gone; the census's trees unchanged; `make focused` exit `0`.
  Priority: **high** — a crash and an out-of-memory from inputs a few kilobytes long.
  **Closed `2026-09-30`.** `MAX_INSTANCES = 1024` and `MAX_IMPORT_DEPTH = 16` in `crates/eadl-front/src/module.rs`,
  both checked in `instantiate` before a module is loaded. The first import past either limit is refused
  (`module-too-many-instances`, `module-import-too-deep`), and an `exhausted` flag drops every later import
  silently, so the work past a limit is none. `reference.md` §6 gains rule 11, and §4 two rows whose `fires on`
  cells are generated trees, executed by `fires_on.rs`. `module_cases.rs` lists the two codes as reached by those
  cells rather than by a tracked fixture, with the reason. The book's modules chapter gives the measurements.
  ⛔ Two expectations of mine were wrong, and the code was right. After a refusal, the instances already begun
  finish on the way back up, so a refused chain keeps its 16 modules and a refused wide tree its root and 1 023
  leaves. That is still exactly the limit's worth.
