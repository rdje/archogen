  Impact: F05's requirement is only half delivered. "An irrelevant capability left undescribed does not fail
  generation" is enforced and tested (`crates/eadl-model/tests/f04_f06_presence.rs`); "remains visible in
  metadata" is computed, asserted by that same test, and shown to nobody — so an author cannot see what their
  description leaves undescribed, which is precisely the information that tells them whether the closure the
  engine computed is the one they meant.
  ⛔ **And the category has nowhere to live, which is a design question and not an oversight.** §4 rule 1 of
  `docs/semantics/reference.md` states that every diagnostic is an error and that there is no warning and no
  note anywhere in the toolchain, with its reason recorded ("a severity that said 'probably fine' would be a
  lie") — while §5.3 requires a fact that is *not* an error to stay visible. Either it goes into report
  metadata through the `archogen-evidence` vocabulary, which is what §7.3's evidence categories are for and
  what the field's name suggests, or §4 rule 1 changes and a warning severity exists — a language change, so
  a migration note. The choice belongs on this leaf with both costs measured, and `M1.26.1`'s normative
  document has to state whichever is chosen.
  Acceptance: the closure boundary an author is told about — what is inside it, what is outside it and
  undescribed, and which request pulled each fact in — reaches a user through a **named** channel, with the
  channel chosen on the leaf and the reason recorded; a leg that fails when the report stops carrying it, so
  a computed-and-dropped field cannot silently return; `docs/book/src/presence.md` saying what the reader
  will see; §4 rule 1 either unchanged and consistent with the choice or amended through a migration note;
  RED arms with the violation count pinned; `make focused` exit `0`.
  Priority: **medium** — no live false claim, because nothing says the metadata is shown, but a roadmap
  requirement measured as undelivered and a second instance of the shape `M1.28` was: a computation whose
  result no consumer surfaces.
  **Channel chosen: the `archogen check` report, as metadata after the verdict** — not a warning severity. §4 rule 1's
  reason ("a severity that said 'probably fine' would be a lie") stands, and the fact outside the closure is not
  "probably fine" either: it is *not needed*, which is information, not a judgement. A warning would have been a
  language change (a migration note) to carry something that fails nothing; the report carries it for free, and
  `docs/semantics/model.md` §2 rule 4 states the channel. The `archogen-evidence` vocabulary was the other
  candidate and is for evidence about a *system*; this is a fact about a *description*, printed where the
  description's verdict is.
  Verification: see the checklist — the boundary in `Outcome`, printed on acceptance; a leg over every accepted
  description the repository records; F05's fixture shown to the author; a catalogued drop-the-report mutation.
