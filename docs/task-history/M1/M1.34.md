- ID: `M1.34`
  Status: `done`
  Goal: `Rational`'s ordering is exact, so a quantity comparison can never report two different amounts as
  equal — and a description whose task deadline exceeds its period is refused however many digits it is
  written with.
  Reproduce / issue: found `2026-09-29` while designing `PROGRAM.9.2`'s fuzz properties, by reading the claim
  in `crates/eadl-model/src/rational.rs`'s `impl Ord`: "saturation preserves the sign of the comparison at the
  extremes where an exact product would overflow". It does not when **both** cross products saturate:
  ```text
  a = (2^100 + 1) / 2^30,  b = (2^100 + 3) / 2^30
  a == b -> false;  a.cmp(&b) -> Equal          (true order: Less)
  ```
  Reached from a description through `Quantity::compare`, which three verdicts use — the offered/required
  match (`quantity.rs:226`), `equals` (`:375`) and §3.1's constrained-deadline rule (`workload.rs:149`).
  Measured with `archogen check` on `examples/periodic-three/system.eadl`, its first task's period and
  deadline replaced:
  ```text
  deadline 2 ns                    period 1 ns                     -> exit 12, "longer than its period"
  deadline 1.003 ns                period 1.001 ns                 -> exit 12, "longer than its period"
  deadline 1.00000000000000003 ns  period 1.00000000000000001 ns   -> exit 0   ⛔ accepted
  ```
  In base units both are fractions over 10^26 s, so both cross products (~2^143) saturate to `i128::MAX`.
  Census: `git grep -n saturating_mul -- 'crates/*.rs'` → rational.rs:255–256 only; the other saturating calls
  are bounded index, length and time subtractions, not comparisons.
  Acceptance: `cmp` compares the cross products exactly (a 256-bit product from 64-bit limbs; no dependency);
  `Ord` agrees with `Eq` for every pair of normalized values; the reproduction pair orders correctly; the
  long-decimal deadline description is refused with the same diagnostic as the short one; the false comment
  is replaced by what is true.
  Priority: **high** — a wrong verdict from the checker's own arithmetic, the §5.3 failure mode.
  Verification: see the checklist — unit and description-level regressions, the old comparison restored as a
  mutation, every tracked description's verdict before and after, the CLI reproduction re-run.
  Commit: `ARCHOGEN-M1-0128 (leaf M1.34)`
