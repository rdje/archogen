  ### Acceptance Checklist (enforced by `TASK-ACCEPTANCE`)

  - [x] **ROOT CAUSE (WHY + WHERE)** — `M1.11` made the grammar normative and proved the reader
    and the EBNF agree on acceptance *and* token segmentation, but both arms are archogen's own.
    §12 M2's standard — a checker "sharing the same erroneous recurrence with its reference does
    not qualify as independent" — applies to the frontend exactly as it does to the runtime, and
    nothing in the tree supplied a reader written by anyone else. WHERE: the gap is `M1.11`'s own
    closing paragraph, which scopes the conformance claim to "the normative grammar and the
    reader" and leaves a third opinion unowned. LinkedSpec was proposed as that third opinion;
    the question is decidable only by running it, and the upstream guide names ARCHOGEN in its
    own example, so the evaluation was owed in both directions.
  - [x] **ADDRESSED (verified)** — measured, not read. The documented vendoring layout does not
    build inside a Cargo workspace: `cargo` reports `could not compile` upstream of two manifests
    with "current package believes it's in a workspace when it's not", and the PGEN bootstrap
    exits `rc=101` for the same reason. With an empty `[workspace]` table added to both, the
    bootstrap reaches `Bootstrap complete` (`rc=0`) and `lispish_file` builds
    (`cargo build … Finished` in 33.94s, rustc 1.95.0). Against that working build, twelve probes
    drawn from real eADL constructs were executed and frozen in
    `docs/feedback/linkedspec/probes/EXPECTED.txt`. The decisive one is not a probe but the real
    fixture: `lispish_file --grammar specs/Lispish.spec examples/s0-heartbeat/system.eadl`
    returns only `["defblock","console.uart",…]` at `exit=0` — three of four top-level
    declarations silently discarded on a success exit. **Verdict: the shipped grammar cannot be
    archogen's reader nor an independent cross-check**, because eADL's normative production
    `document = { trivia } , { form , { trivia } } , end` requires every form and an explicit
    end-of-input, and a recognizer that accepts by ignoring agrees on every accept and refuses
    nothing. The engine is not disqualified — `linkedspec-runtime` is correctly insulated by its
    own workspace root — so the route stays open behind an upstream complete-input mode.
  - [x] **NO REGRESSION** — no archogen crate, manifest or test was touched by this leaf: the
    staged set is documentation, two reproducer scripts, a probe corpus and a submodule pointer.
    `bash scripts/check_doctrines.sh` → `=== all doctrines green ===`; `bash -n` clean on both
    new scripts; the reproducer is self-checking and reports
    `RESULT: reproduced (2/2) and fixed by the proposal (2/2).` at `rc=0`. The `M2.9` working set
    is untouched and still unstaged — `git diff --name-only` lists exactly the seven `M2.9` files
    and nothing from this leaf.
  - [x] **REPRODUCE** — `bash docs/feedback/linkedspec/repro/repro-workspace-collision.sh
    <linkedspec>` reproduces the build blocker from any LinkedSpec checkout and asserts the
    proposed fix resolves it; `bash docs/feedback/linkedspec/run-probes.sh` replays the twelve
    Lispish observations and diffs against the frozen `EXPECTED.txt`.
  - [x] **LOCKSTEP** — `docs/feedback/README.md` indexes the new outbound-feedback layer;
    `.gitignore` excludes the application-owned `.app-data/` build root the upstream guide
    requires. The frontier does not move: `M1.12` remains next, so `docs/TASK_TREE.md` is
    unchanged by design.

  ### What this establishes, and what it does not

  It establishes that **the shipped Lispish grammar is an extraction tool, not a validator**, and
  that archogen measured this rather than inferring it from the upstream guide — which documents
  the behaviour honestly and predicted it. It does **not** establish that LinkedSpec's engine is
  unsuitable: the one change that would decide it, a complete-input mode, is upstream work
  archogen does not own. Until that exists, `M1.11`'s two arms remain archogen's own, and the
  third independent opinion stays an open question rather than a closed one.

  ⚠️ This leaf deliberately produced **no archogen code**. The vendored submodule is a
  development-time evaluation dependency and is not referenced by any crate; nothing in the
  build, the tiers or the shipped toolchain depends on LinkedSpec.
