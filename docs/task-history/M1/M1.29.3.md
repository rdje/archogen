  Status: `done`
  Design, decided `2026-09-29` and written into `docs/semantics/reference.md` §6 before any code:
  **(a)** rule 9 — an elaborated declaration is named by its instance path, `platform.timer.timer.counter`,
  which is the name `Program::qualified_declarations` already computes and `modules.md` already shows.
  **(b)** rule 10 — the operands of `uses`, `needs` and `refines` (the clauses `presence.rs` reads as names,
  and the only ones) resolve in the writing instance's scope: its own declaration first; then `alias.n`
  through one of its imports, where `n` must be **exported** by that import's module, else the new code
  `module-not-exported`; else the name is left as written, because it is a capability-vocabulary name and
  not a declaration's. An alias never shadows a local declaration. There is no re-export, so an importer
  sees exactly the exports of the modules it imports directly — `app.system` cannot reach
  `platform.timer.…` unless `hw.soc` declares and exports something that stands for it. **(c)** Layering:
  the frontend owns the scope (`Program::resolve`, and the new code's literal, so §4's census still finds
  every `module-` code in `module.rs`); the model layer owns *which positions are names* and applies it
  (`eadl_model::check::check_program`), because the kind schema holds those clauses as plain forms. **(d)**
  The passes then run over the resolved declarations unchanged — `check` and `check_program` share one
  pass sequence, so a module tree is judged by exactly the rules a single description is.
  Goal: the **name rule** an elaborated program needs — how a reference written inside an instance resolves,
  and what an `export` hides from an importer — written into `docs/semantics/reference.md` §6, then
  implemented, so an elaborated program can be handed to the model passes; and with it, `archogen check`
  elaborating **and** type-checking a module tree end to end.
  Acceptance: the rule stated with its reason before any code (§6 today says only that what an import
  brings in is "addressed by the dotted path of aliases from the root"); the model passes run over the
