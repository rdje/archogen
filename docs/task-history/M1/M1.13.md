  ### Two findings routed here by `M1.12`, because freezing is what settles them

  Both are limits of the *value domain*, measured by the 39-literal probe on `2026-09-28`, and neither
  can be fixed by a sentence in the reference — each changes what the language can express, which is
  exactly the decision a compatibility baseline makes once and for all. ⛔ **Re-measured `2026-09-28`

  a premise the pinned ISA spec contradicts, and F-G's fix shape is constrained by an enforcement
  boundary the routing did not consider.

  - **F-F — no value at or above 2^63 is writable.** `Form::Integer` holds an `i64`, so
    `0x8000_0000_0000_0000` is refused as `read-number-overflow` (re-measured, M-A). ⛔ **The impact
    `M1.12` recorded is corrected here rather than carried forward.** It said a memory-mapped base
    address in the upper half of a 64-bit address space cannot be described, and that `M2.8.2`'s
    device-tree fixture is where that would first matter. The premise is false for every standardized
    target (M-D): RV64's PMP registers encode bits 55-2 of a **56-bit** physical address, Sv39 and
    Sv48 support a 56-bit physical address space, Sv57 is **57-bit virtual**, and Sv64 is reserved and
    unimplemented — so no address a standardized target can have reaches 2^57, against a domain limit
    of 2^63−1. The finding stands as a stated limit of the version; the urgency routed with it does
    not. Owner: `M1.13.2`.
    ✅ **SETTLED by `M1.13.2`, and its own correction was corrected in turn.** The domain stays exact
    signed 64-bit for `eadl/1`, now as a **stated property of the version** (§1 rule 9) with the
    widening path recorded in `docs/decisions/decision_eadl1-value-domain.md`. ⛔ The sentence above
    did not survive re-derivation either: "no address a standardized target can have reaches 2^57" is
    true of *physical* addresses and false of canonical *high-half virtual* ones, which are refused
    today in their unsigned spelling under Sv39, Sv48 and Sv57 alike (N-D), and Sv64 is not merely
    reserved — the pin says it "will be defined in a later version". The decision is unchanged and now
    rests on a reason that survives the measurement: a widening is compatible, every value that needs
    one is already reachable as a signed value, and §1 rule 10 states the cost out loud with two rows
    executing it.
  - **F-G — a control character other than `\n \t \r` cannot be escaped.** `write_canonical` escapes
    four characters and copies everything else, so a string holding a raw control byte prints it into
    canonical text (re-measured, M-B: ESC, BEL and **NUL** each read cleanly and each print raw).

    routing did not carry, each measured below: the reader *already* refuses the same byte between

  ### Design constraints, recorded so the child does not have to re-derive them

  - ⛔ **The escape must be in the language, not only in the printer.** §3 rule 5 requires canonical
    text to read back to a structurally equal document. A printer that escapes a control byte into a
    notation the reader refuses produces canonical text that is not a description — which would trade
    F-G for a round-trip defect. This is why the reference's "either a general escape **or** a rule that
    a description may not contain one" is not a free choice: the second alone leaves the printer
    non-total, and M-F shows a value can reach the printer without passing the reader.
  - ⭐ **Both legs, and the order matters.** Refusing the byte at read time closes the route through
    source text; making the printer total closes every route. `docs/knowledge/make-the-rule-a-constructor-precondition.md`
    is the card: look for the illegal *state* (canonical text holding a control byte) rather than the
    illegal *action* (someone typing one into a file), and refuse it where the state is produced.
  - ⚠️ **The grammar change is a frozen-construct change and `.4` has not run yet**, so it costs no
    migration note. That is the whole reason `.1` is sequenced first, and it is the last moment the
    escape set can be widened for free.
  - Surrogates (`D800`–`DFFF`) are not Unicode scalar values and a Rust `char` cannot hold one, so the
    general escape must refuse them explicitly rather than panic or truncate. Whichever notation is
    chosen, `decode_escapes` and `encode_canonical` in `crates/eadl-front/tests/common/reference_table.rs`
    are the shared pair that must stay inverse — the existing legs already read both.

  **Keep the exact 64-bit signed domain for `eadl/1`.** Three measurements, not a preference. ⛔ **Both
  of the measurements this argument was drafted on moved when `M1.13.2` re-derived them, and the
  argument is restated here in its corrected form — the record of the original is on M-D's and M-G's

     limit of 2^63−1. The census agrees from the other side and is now re-runnable: the largest literal

     literals in it are refused by the domain. ⛔ The half this argument got wrong: a canonical

     magnitude, so the honest reason to defer is not "nothing needs more" but "everything that needs
     more is already reachable as a signed value, and the unsigned spelling is a compatible widening".
     Sv64 is not merely reserved either: the pinned spec says it "will be defined in a later version".
  2. **Widening moves the hole, it does not close it.** `Form::Decimal` holds digits and a scale, so
     `i128` would leave the same class of limit one width up. Only arbitrary precision removes it, and
     the workspace carries **zero** third-party dependencies — a property `decision_zero-dependency-engine-core.md`
     records and §10.4's trust argument rests on — so arbitrary precision means hand-written arithmetic
     in the one crate every other layer's exactness depends on.
  3. **Deferring is cheap in a way that deferring most language changes is not.** A widening is
     *backward compatible*: every literal readable under `eadl/1` stays readable and keeps its value,
     so no description needs migrating and the only cost is one added compatibility-corpus row. That is
     the property §15 actually cares about — "a source description retains its meaning under its locked
     semantic version" — and a widening preserves it by construction.

  ### The design constraint that decides this, measured rather than argued

  ⛔ **The identifier cannot ride the comment-header convention, however convenient that looks.** The
  header route needs no grammar change, §5 already makes one shape of comment data, and
  `Document::comment_headers()` already reads it — so it is the obvious candidate and it is wrong here.
  §3 states that canonical form carries **no comment**, and §12 M4 hashes canonical plans. A version
  that lives in trivia is therefore a version the hashed artifact does not capture: two descriptions
  differing only in the language version they claim would hash identically, and any tool that strips
  comments would silently strip the lock with them. A version identifier has to survive canonicalization,
  which means it has to be a **form**.

  What that costs, stated so the choice is made with the price visible: a new top-level form is a
  grammar change, so `docs/semantics/grammar.md`'s `document` production and
  `crates/eadl-front/tests/conformance.rs`'s probe set both move, and the reference's §4 gains rows.
  That is exactly the work `.1` establishes the pattern for, and it is free only because it lands
  before `.4` writes the baseline.

  ⚠️ Decide and record, do not drift into it: whether an **absent** identifier means `eadl/1` or is
  refused. Defaulting is friendlier to the 62 existing corpus files and weaker as a lock — §15's word
  is *locked*, and a version nobody wrote is a version the toolchain inferred. Refusing is a
  strengthening that pre-freeze costs one pass over the corpus. Whichever is chosen, the reason goes in
  the decision record with the census of what it touched.

  decides it.** Raised `2026-09-29`; the measurements and the three candidate readings are in
  `## Open Questions` above. In one line each: the acronym `eADL` is expanded **nowhere** in the
  repository, the director supplied **Extended Architecture Description Language** while unsure what it
  extends, and "Extended ADL" cannot be a claim about the syntax because the ADL tradition (Acme,
  Wright, Rapide, UniCon, C2, Darwin, AADL/AS5506) carries bespoke notations and none of it is
  s-expression based.

  ⭐ **The director's stated reason for the syntax picks the reading:** *"What I really like about
  Lispish language or S-expressions is that code and data wear the same cloth, that is they have the
  exact same syntax and it is inherently extensible."* That is reading **(b)** — extended as
  **extensible** — and it is not an aspiration in this repository, it is already executed: one `Form`
  type carries a description and any data inside it alike, and `defkind` grows the language using the
  language's own declaration construct (§7 of the reference, made a machine-read declaration by
  `M1.12.4`, with §5.6's prohibition enforced against the facility that declares the language).

  ⛔ **State the limit beside the claim, or the word oversells.** eADL is homoiconic in its *syntax* and
  deliberately not in its *execution*: there is no `eval` and no macro system, so a description cannot
  rewrite itself. That is `decision_eadl-engine-boundary` — eADL contains no implementation, and a macro
  is implementation. The engine interprets the forms; it is Rust, and it is not written in the language
  it reads. What "code and data wear the same cloth" buys here is that **the language is extensible by
  its own users without a new parser**, not that it is a Lisp.

  ⚠️ And the cost, which is this tree's actual history rather than a caveat: a uniform syntax makes
  well-formedness and meaning come apart, so the reader accepts forms the semantics must then refuse.
  Every finding in `M1.12` is that shape — `0x_10` read as 16 while the grammar refused it (F-B), a
  grammar accepting a raw line feed the reader refused (`M1.13.1`), and a well-formed literal outside
  the value domain being *refused* rather than *errored* (`M1.13.2`), a distinction that exists only
  because the two questions are separate. That is why `docs/semantics/reference.md` exists at all, in
  its own words: a grammar proves two implementations accept the same language and "says nothing about
  the value behind a token". Extensibility is the reason the language is s-expression shaped, and the
  second normative document is the price. ⭐ **`M1.13.3` paid that price again and it is worth naming:**
  `(eadl-version eadl/1)` is a perfectly well-formed form that the grammar always accepted, and three
  separate layers then had to be told what it *means* — the reader validates it, `module.rs` must not
  count it as a stray declaration, and `check.rs` must not validate it as a kind. Uniform syntax is what
  makes all three possible and what makes all three necessary.
