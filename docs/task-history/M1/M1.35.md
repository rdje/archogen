- ID: `M1.35`
  Status: `done`
  Goal: the reader survives every text: an unknown escape before a multi-byte character is reported, never a
  panic.
  Reproduce / issue: found `2026-09-29` while choosing `PROGRAM.9.2`'s fuzz targets, by reading the escape arm
  of `crates/eadl-front/src/reader.rs`: an unknown escape takes one **byte** (`other as char`) and advances
  one byte, which strands the reader inside a multi-byte character.
  ```text
  $ archogen check <(eadl-version eadl/1) (defkind x (doc "a\éb"))>
    thread 'main' panicked at crates/eadl-front/src/reader.rs:292:38:
    start byte index 42 is not a char boundary; it is inside 'é' (bytes 41..43)          exit=101
  ```
  Probed alongside, each through `archogen check`: `(a é b)`, `é`, `(a \é)`, `"\u{é}"`, `"\u{1F600}é"`,
  `(a 1é)`, `(a 1.5é)`, `(a -é)`, `(a 0xé)`, `;é comment`, `(a "é")`, `)é` — ordinary diagnostics or
  exit 0, no panic. The escape arm is the one crash found by hand; `PROGRAM.9.2`'s fuzz is the wider search.
  Acceptance: an unknown escape is read as one whole character — the diagnostic names it (`\é`), its span
  ends on a character boundary, the string keeps the characters literally as today; a test at the reader
  and one through the CLI's exit contract; the fix restored away is caught.
  Priority: **high** — a crash on user input, where the contract is a diagnostic and exit 10.
  Verification: see the checklist — a reader test at two widths, an in-process CLI test, the byte-wise read
  restored as a mutation, every tracked description's verdict before and after.
